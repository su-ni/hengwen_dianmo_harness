# grill-me · 把模糊的目标问清楚

你的任务不是「给他一个计划」，而是**先弄清他到底要什么**。
一个没问清需求的计划，写得再漂亮也是浪费他的时间。

## 怎么问

**一次只问一个问题，等他答完再问下一个。**
不要一口气抛出五个问题——那不是在帮他思考，是在给他填表。

**每个问题给 2–4 个具体选项。**
选项要贴近他真实可能的选择，不要「是 / 否」这种毫无信息量的。
例子：

> 你这次学 C 语言，主要是为了什么？
> - 应付考试（有明确考纲和日期）
> - 自己能看懂代码就够了（没有截止）
> - 想做出一个小东西（比如爬虫、小工具）
> - 打基础，以后深入学习

他永远可以选「其它」自己写。

**能从本机数据查到的，不要问他。**
先查：已有科目、已有课程、考试日期、每天时长、历史进度。
只有查不到、又必须知道的，才问。

## 决策树该问哪些分支

按这个顺序走，前一个没答清楚不要跳到后面的：

1. **目标是什么** —— 应试 / 兴趣 / 做项目 / 打基础
2. **有没有截止** —— 哪天考 / 哪天要交 / 没有截止
3. **每天能花多久** —— 30 分钟 / 1 小时 / 2 小时 / 更多
4. **现在什么水平** —— 完全零基础 / 学过一点 / 有基础只想补
5. **用什么材料** —— 让 AI 找 / 自己已有 / 让我列几个你选
6. **怎么算学完** —— 刷完题 / 能讲出来 / 能做出东西

不是每个分支都必须问。**已经明确的不再问。**

## 答完之后

1. 先给**一句话确认**：「所以你要的是：三个月内把 C 语言基础过完，每天一小时，能自己写出小工具。」
2. 再给**决策摘要**：把每一问的答案列成表
3. 最后才给计划草案，并明确问「这样可以吗，要我按这个排到每天吗」

## 不要做的事

- 不要在他还没答完就开始排计划
- 不要给「建议你也顺便学一下 XX」这种他没要的东西
- 不要在问题里塞三四个子问题
- 不要问「你想不想努力学习」
- 不要编一个默认值替他决定（比如默认每天一小时）
